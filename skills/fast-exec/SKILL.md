# fast-exec

## Language

All skill operation, subagent prompts, status reports, and user-facing responses must be in English.

## Overview

Execute the plan by **dependency layers**, with parallel subagents for `[P]` tasks
and **one review per layer**. The `tasks.md` is the **contract**: do not replan,
reorder, or invent tasks. Serious plan gap → stop and ask the user.

**Announce:** "Using fast-exec to execute the plan."

**Continuous execution:** do not pause between tasks/layers for confirmation.
Stop only for unresolvable BLOCKED status, real ambiguity, or end of plan.

## Protocol

1. **Worktree:** confirm you are in the initiative worktree (helix rule — never
   implement in a root repo).
2. **Single load:** read the plan ONCE; extract the Context Pack and all tasks with
   full text; validate file disjointness for `[P]` tasks by layer (overlap → treat
   as sequential and report it); create TodoWrite.
3. **Per layer (L1 → L2 → …):**
   - Dispatch all `[P]` tasks in the layer **in parallel** (one Agent call per task,
     in the same message). Tasks without `[P]` run serially.
   - Model by tier: `[fast]` → fast model (sonnet); `[opus]` → opus.
   - Implementer prompt: full task text + Context Pack + instructions below.
     **Never** tell the subagent to read the plan.
4. **Controller commits:** subagents DO NOT commit. At the end of the layer, the
   controller makes **one commit per task** (disjoint files allow clean staging),
   using conventional messages.
5. **Layer gate:** run the relevant test suite; then ONE review (subagent **Opus**)
   over the layer diff covering spec compliance + quality. Failed review → fix
   subagent (same task context) → re-review. Advance only with a green gate.
6. **End of plan:** full suite + `superpowers:finishing-a-development-branch`.

**Override:** if the user asks (for example, sensitive code), replace the gate with
review per task — same format, smaller scope.

## Implementer prompt (mandatory summary)

- Context: where the task fits (1–2 sentences) + Context Pack verbatim.
- Complete task (files, acceptance, tests, design).
- **Mandatory TDD** (superpowers:test-driven-development): failing test → minimal
  implementation → green.
- **DO NOT commit, DO NOT touch files outside the task file list.**
- Final report: `DONE` | `DONE_WITH_CONCERNS` | `NEEDS_CONTEXT` | `BLOCKED`
  + summary of what changed and test results.

## Status handling

| Status | Action |
|---|---|
| DONE | Continue to layer commit/gate |
| DONE_WITH_CONCERNS | Read concerns; correction/scope issue → resolve before gate; observation → note it |
| NEEDS_CONTEXT | Provide missing context and re-dispatch |
| BLOCKED | Escalate model (`fast`→`opus`), split the task, or stop and ask. Never re-dispatch unchanged |

## Red flags — stop and fix

- Subagent commits or edits files outside the task.
- `[P]` tasks dispatched with overlapping files.
- Advancing layers with failed review or red tests.
- Replanning/rewriting tasks instead of asking.
- Implementing in a root repo or outside the initiative worktree.
- Telling a subagent to read the plan instead of providing the text.

## Scale

Plan with 15+ tasks or very wide layers: consider orchestrating execution with the
Claude Code **Workflow tool** (`pipeline()`/`parallel()`, worktree isolation) —
optional, same contract and same gates.
